# Правила для ИИ-агентов

Проект реализуется автором вместе с ИИ-агентами. Эти правила обязательны.

## Перед работой

1. Прочитай `docs/00-vision.md` (реестр решений D1–D36 и далее) и документ по своей задаче.
2. Решения из реестра не пересматривай молча. Если задача требует отступить —
   остановись и спроси автора; после согласования обнови реестр в том же PR.
3. Найди задачу в `docs/06-roadmap.md` и её критерий приёмки.

## Методология и данные

- Любая цифра на экране — измерение, откалиброванная величина или явная «оценка».
  Третьего не бывает.
- Изменение формулы, признака, целевой переменной или порога — только вместе
  с обновлением `docs/03-methodology.md` и повторным бэктестом.
- Признаки строятся только по данным, доступным на дату `t`, с учётом
  публикационных лагов. Утечку будущего ловит тест — его нельзя отключать.
- Не парсить сайты вопреки их правилам. Новые источники — через `config/sources.yaml`
  с лицензией и условиями.
- LLM — только операции A1–A4 из `docs/05-ai-policy.md`. LLM не пишет цифры.

## Код

- Python 3.12, `uv`, DuckDB/Polars; TypeScript strict, React, MapLibre GL, deck.gl.
- Файлы до ~500 строк; публичные функции и API типизированы; входные данные
  валидируются на границах (Pydantic / zod).
- Тесты обязательны для ETL-преобразований, методологии (утечка, суммы вкладов),
  валидации query-spec. Запускай их перед PR.
- Одна задача — одна ветка — один PR; в описании — критерий приёмки и доказательство.

## Секреты и сервер

- Никогда не коммить секреты, `.env`, данные (`raw/`, `marts/`, `*.parquet`).
- Не читай и не выводи значения ключей LLM и токенов.
- Сервер `194.87.187.207` общий ещё с 9 сайтами. Проект живёт только в
  `/opt/rf-analytics`, порты не публикуются, сеть `edge`. Конфиг edge-прокси
  менять только так: бэкап → `caddy validate` → `caddy reload`. **Никогда не
  делать restart edge-caddy** и не трогать чужие стеки.
- Статику публиковать `rsync -a --delete` внутрь существующего каталога (не `mv`).
- Деплой-ключ проекта — `~/.ssh/id_ed25519_rf_analytics` (локально) /
  `RF_DEPLOY_SSH_KEY` (Actions). Другие ключи не использовать.
