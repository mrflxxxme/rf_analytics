# 08. Пробник источников (T1.1), 17.10.2026

Скрипт `scripts/probe_sources.py` (только stdlib) делает GET с `Range` на первые
2 КБ, тело не сохраняет, пауза 1 с между запросами. Workflow
`.github/workflows/probe-sources.yml` гоняет его на раннере GitHub и, через
ключ деплоя, на сервере. Описание источников — `config/sources.yaml`.

Точки наблюдения:

- **local** — машина автора, выход через VPN (Нидерланды);
- **actions** — `ubuntu-latest` GitHub (США);
- **server** — 194.87.187.207 (РФ). **Не снят:** из Actions SSH доходит,
  но ключ `RF_DEPLOY_SSH_KEY` для пользователя `deploy` отклонён
  (`Permission denied (publickey)`). С local SSH виснет на обмене баннерами.
  Нужен публичный ключ в `~deploy/.ssh/authorized_keys`, иначе T1.3/T1.4
  не заработают. После этого перезапустить workflow.

корневой сертификат в свой trust store (не `verify=False`).

## Что это меняет

1. **Реестр МСП качаем в Actions, а не на сервере.** Сервер (2 ядра, ~3 ГБ RAM)
   не трогаем гигабайтами. На раннере 14 ГБ диска: снимок 2,1 ГБ скачивается,
   стримится через XML-парсер в компактный Parquet и удаляется. Решение D34.
2. **В снимке нет даты и причины исключения.** Есть дата включения, вид,
   категория, признак «вновь созданный», ОКВЭД, код региона. Исключение —
   ИНН исчез в следующем снимке. Закрытие и потерю статуса МСП по самим данным
   не различить: это шум, как и предусматривает `docs/02-data-sources.md`.
3. **ЕМИСС — только сервер.** Значит, T1.8 зависит от доступа к серверу.
4. **СберИндекс без регионального API.** Вторичная цель D15 (траты) и слой
   «спрос» в T3.4 пока держатся на архиве хакатона (2023–2024) и PDF-релизах.
   Это риск для T3.4, решение отложено до него.
5. **hh.ru:** автору зарегистрировать приложение на dev.hh.ru до T3.4.
6. **Миграция «откуда → куда»:** в оглавлении бюллетеня матрицы нет, только
   прибытие, выбытие и сальдо по субъекту. Полная проверка листов — в T2.3;
   если матрицы нет, слой D21 «миграционные потоки» строится по сальдо или
   из другого источника. Это вопрос к автору на T2.3.
