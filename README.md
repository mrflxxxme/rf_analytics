# Радар потребностей регионов РФ

Открытая система предиктивной аналитики. Она показывает, **что может понадобиться
в регионах и крупных городах РФ в ближайшие 6–18 месяцев**: где спрос растёт,
деньги у людей есть, а предложения не хватает. Главный экран — интерактивная карта,
на которой видны связи между регионами: волны трендов, миграция, влияние событий.

> Статус: **публичная бета «факты» — веха M1 принята 21.10.2026**. Имя продукта — «Нишемер».
> Бета открыта на временном адресе <https://nishemer.194.87.187.207.sslip.io/> (`noindex`),
> постоянный адрес — nishemer.ru после регистрации домена (D37, [roadmap](docs/06-roadmap.md)).
> На экране только измеренные данные реестра МСП ФНС; прогнозов пока нет.

## Принципы

1. **Проверяемость важнее эффектности.** Каждая цифра на экране измерена либо
   откалибрована бэктестом. Модельные оценки помечаются отдельно.
2. **Потребность = разрыв**, а не популярность. Спрос и деньги сопоставляются
   с плотностью предложения у сопоставимых регионов.
3. **ИИ только там, где без него ценности нет.** Это четыре операции: извлечение
   драйверов из текстов, перевод вопроса в запрос конструктора, идеи для досье,
   черновики постов канала по витринам. Цифры ИИ не пишет никогда.
4. **Дёшево и быстро.** Бюджет — до ₽150 тыс. на 10 недель. Сбор данных идёт
   в GitHub Actions, сервер только отдаёт результат.
5. **Простой интерфейс.** На экране одна метрика, не больше трёх слоёв связей,
   подробности открываются по запросу.

## Структура репозитория (целевая)

```
config/      таксономия, семантический слой метрик, источники, LLM-маршруты
etl/         Python: сбор данных → нормализация → признаки → модель → бэктест → витрины
api/         FastAPI + DuckDB только на чтение поверх Parquet-витрин
web/         Vite + React + TypeScript + MapLibre GL + deck.gl
deploy/      docker compose стека, Caddyfile, скрипты сервера
tests/       тесты ETL, методологии и API
docs/        документация
.github/     CI, ежемесячный ETL, дообогащение по запросу, деплой
```

## Данные и лицензии

Код открыт. Сырые и рассчитанные данные **в репозиторий не попадают**: они
хранятся на сервере. Используются только открытые и лицензионные источники,
сайты не парсятся вопреки их правилам (см. [источники](docs/02-data-sources.md)).
